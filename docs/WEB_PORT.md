# Сборка и запуск BitCraft Companion

BitCraft Companion собирается из `web/` и работает как статический сайт. Расчёты выполняются в браузере. В выпуск входят закреплённый снимок игровых данных и локальные изображения.

## Запуск

В Windows дважды щёлкните [Start-Web.cmd](../Start-Web.cmd) в папке проекта. Скрипт запускает готовый пакет `dist-web/`, а при его отсутствии сначала собирает пакет. Оставьте окно запуска открытым на время работы. Для завершения нажмите Ctrl+C.

Локальный сервер открывает текущую сборку по `http://127.0.0.1:4173/online.html`, даже если браузер ещё держит предыдущий автономный выпуск. Оба адреса используют те же планы и запасы. Чтобы применить новый выпуск и к автономному адресу `http://127.0.0.1:4173/`, нажмите «Обновить» в верхней панели сайта, когда кнопка появится.

Скрипт запускает Node.js напрямую и может использовать Node из установленного Codex. Для запуска из терминала подходит полный путь к `Start-Web.cmd` из любой текущей папки.

Чтобы пересобрать веб-версию после правок, остановите локальный сервер. Откройте терминал в папке проекта и запустите команду при доступном `npm`:

```powershell
npm run web:dev
```

Команда собирает `dist-web/` и запускает preview по `http://127.0.0.1:4173/online.html`. Откройте напечатанный адрес в браузере. После изменения исходников перезапустите команду, чтобы опубликовать новый выпуск. Завершение — Ctrl+C.

Сборка и preview по отдельности:

```powershell
npm run web:build
npm run web:preview
```

Другой порт и размещение в подпапке:

```powershell
npm run web:preview -- --port 4180 --base-path /companion/
```

Адрес без завершающего `/` перенаправляется на адрес каталога. Открытие `index.html` через `file://` не поддерживается. Для service worker требуется HTTPS; loopback подходит для локальной разработки. Обычный HTTP на IP другого компьютера не обеспечивает автономный режим.

## Возможности и данные

Веб-сборка включает все вкладки, в том числе «Мир» с достижениями, биомами и разведкой, «Данжи», четыре режима ресурсов и справочник профессий, знаний и квестов. Экспорт использует формат `version: 1`. Состояние браузера хранится под ключом `bitcraft-companion-v1`. Каталог и картинки хранятся отдельно.

У сайта отдельные сохранения в текущем профиле браузера. Они не отправляются на сервер и не синхронизируются между устройствами. Домен, протокол и порт определяют хранилище; изменение локального порта также создаёт другой origin. Очистка данных сайта удаляет сохранения, а приватный режим не подходит для постоянного хранения.

Для переноса сохранений между браузерами и устройствами используйте JSON.

1. В исходном браузере нажмите «Экспорт всех данных».
2. В новом браузере нажмите «Импорт данных» и выберите JSON.
3. Проверьте планы, запасы и собственные рецепты. Импорт заменяет текущее состояние. Прежняя копия сохраняется под ключом `bitcraft-companion-v1-before-import`.

Если новое состояние не удаётся записать, импорт не заменяет рабочие данные в памяти и не сообщает об успехе. При изменении сохранений из другой вкладки устаревшая вкладка приостанавливает запись. Она предлагает экспортировать свою копию или открыть актуальные данные. При доступном Web Locks проверка актуальности и запись выполняются под общей блокировкой вкладок. Без этого API остаётся проверка устаревшей копии; для редактирования используйте одну вкладку. Совместное редактирование с объединением изменений не реализовано.

Таймер по-прежнему считает календарное время до паузы, включая закрытие вкладки. Ограничение фоновых интервалов браузером не меняет его расчёт.

## Адреса

Навигация использует hash-маршруты, поэтому не требует серверного fallback для карточек:

| Пример | Раздел |
| --- | --- |
| `#/drops` | Добыча |
| `#/rarity` | Редкость |
| `#/recipes/family%3Aitem%3A1606324183` | Предмет в рецептурной книге |
| `#/resources/game` | Материалы |
| `#/resources/buildings` | Постройки |
| `#/resources/creatures/enemy%3A9` | Существа, карточка Rangifer |
| `#/resources/custom` | Мои рецепты |
| `#/guide/skills/5/60` | Mining, уровень 60 |
| `#/guide/knowledge/844511805` | Знание Player House Deed 1 |
| `#/guide/quests/1762918554` | Квест The Long Haul |
| `#/world/achievements/106` | Достижение Apprentice Miner |
| `#/world/biomes/1` | Биом Calm Forest |
| `#/world/prospecting/1249466124` | Разведка Survey the Lake |
| `#/dungeons/208697589` | Данж Starseeker Armory |
| `#/time` | Таймер |
| `#/plans` | Мои планы |

Карточки материалов, построек и существ получают идентификатор в конце маршрута. Работают переходы «Назад/Вперёд» и прямое открытие карточки. В URL могут быть раздел, публичный идентификатор сущности и уровень навыка.

## Автономная работа и обновления

При первом посещении service worker сохраняет интерфейс, каталог с русским словарём, индекс изображений и картинки пресетов. Справка «Источники и справка» показывает готовность к работе без сети. Первый запуск и подготовка требуют подключения.

WebP сохраняются по мере просмотра; такой кеш ограничен 200 изображениями. Для непросмотренных картинок доступен кешируемый набор иллюстраций по типам сущностей. В справке есть отдельная кнопка загрузки всех изображений — около 74 МБ, с прогрессом и повтором после ошибки. Она не запускается автоматически. Браузер может удалить кеш при нехватке места; готовность проверяется, а при подключении базовый пакет восстанавливается. JSON-экспорт остаётся резервной копией пользовательских данных.

Новый service worker сначала целиком подготавливает базовый пакет. Неполная загрузка не активирует новый выпуск. Готовое обновление применяется через кнопку «Обновить»; перед перезагрузкой приложение пытается сохранить состояние. Кеши, нужные ещё открытым старым вкладкам, сохраняются. Обновление не очищает localStorage.

## GitHub Pages

Публичный workflow [pages.yml](../.github/workflows/pages.yml) запускается из вкладки **Actions** после выбора **GitHub Actions** в **Settings → Pages**. Для деплоя используется ветка `main`. Артефакт содержит один выпуск из `dist-public/`.

Для локальной проверки того же пакета соберите публичный выпуск и запустите сервер под адресом проекта.

```sh
node scripts/build-web.mjs --public
node scripts/serve-web.mjs --root dist-public --base-path /BitCompanion/ --port 4180
```

Публичная сборка берёт каталог из `data/public/`. Карточки показывают собственные иллюстрации инструментов, материалов, существ и биомов. Набор SVG входит в основной кеш сайта. Подключение внешнего HTTPS-источника описано в [настройке фоновой загрузки](LOCAL_ICONS.md#фоновая-загрузка-в-публичной-сборке). Разделы, расчёты, локализация и сохранения используют те же модули сайта. Для ручного обновления через Pages запустите workflow заново.

## Состав выпуска и размещение

Папка сборки содержит следующий комплект. Публичный выпуск записывается в `dist-public/`, а сборка для локального запуска по умолчанию — в `dist-web/`.

- `index.html`, `sw.js`, `release.json` — вход и текущий выпуск;
- `releases/<release>/` — неизменяемый комплект JavaScript, CSS, каталога, изображений, манифеста и `shell.html`;
- `asset-manifest.json` внутри выпуска — SHA-256 и размеры ресурсов;
- `.gz` и `.br` рядом с текстовыми файлами — подготовленное сжатие;
- `_headers` — правила заголовков для совместимого статического хостинга.

Идентификатор выпуска вычисляется из содержимого и сборщика. Повторная сборка одинаковых исходников воспроизводит тот же комплект. Исходный индекс изображений сохраняет контрольные метаданные; веб-сборка оставляет в исполняемом индексе только используемые связи `images`.

Для публичного размещения используйте собранное содержимое `dist-public/`. Для размещения используйте HTTPS и корректные MIME-типы JS, JSON и webmanifest. GitHub Pages обслуживает эти форматы штатно. `scripts/web-headers.mjs` описывает дополнительные заголовки для локального preview и совместимых хостингов. [MIME-типы GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site#mime-types-on-github-pages).

`_headers` применяется только платформами, поддерживающими этот формат. На другом сервере перенесите правила в его конфигурацию; для подпапки добавьте её префикс к путям. Сжатые sidecar-файлы сервер должен выбирать по `Accept-Encoding` и отдавать с соответствующим `Content-Encoding` и `Vary`; иначе включите собственное сжатие обычных файлов. Не заменяйте JS/JSON HTML-страницей для отсутствующего ресурса.

Для входных файлов используется проверка актуальности (`no-cache`), для URL внутри версии — длительный `immutable`. Версия охватывает и изображения: их прежние хэшированные имена обозначают исходный путь, а не содержимое, поэтому кеширование только по такому имени было бы недостаточным.

При обновлении сначала загрузите новый каталог `releases/<release>/`, затем замените входные файлы согласованным комплектом. Сохраняйте предыдущие выпуски для открытых вкладок. Сборщик не удаляет их автоматически. Неизменяемые каталоги можно удалять только с учётом ещё используемых версий; для архивирования удобнее хранить полные снимки опубликованного `dist-public/`.

Откат выполняется публикацией входных файлов и ресурсов предыдущего полного снимка. Браузер подготавливает его как очередное обновление. Изменение схемы сохранений потребует плана совместимости.

## Проверки

```powershell
npm test
node scripts/build-public-data.mjs --check
node scripts/test-web.mjs --public
```

`test:web` собирает сайт, запускает временный loopback-сервер на свободном порту в подпапке `/companion/` и проверяет интерфейс, навигацию, сохранения и service worker. По завершении сервер закрывается. Проверки используют изолированные браузерные контексты. Снимки сохраняются в `output/`, локальные эталоны хранятся в `docs/design/`. Полный набор проверок с подготовленными локальными таблицами и изображениями запускается командами `npm run test:full` и `node scripts/test-web.mjs`.

Тестовая зависимость Playwright закреплена в `package.json`. Helper сначала ищет установленный Playwright проекта, затем bundled runtime Codex; скачивание браузеров тестами не выполняется. Если Chromium отсутствует, в Windows может использоваться установленный Edge. Для отдельного набора можно задать:

```powershell
$env:BASE_URL = 'http://127.0.0.1:4173/'
$env:BROWSER = 'chromium'
node tests/web-ui.cjs
```

`BROWSER` также принимает `firefox` и `webkit`; нужен соответствующий установленный браузер Playwright. `BROWSER_EXECUTABLE_PATH` задаёт явный путь к совместимому executable. Проверка жизненного цикла service worker использует Chromium и пропускается на других движках. В текущем окружении доступны проверки Edge; Firefox/WebKit и реальные мобильные Safari/Chrome требуют отдельного прогона.
