# BitCraft Companion: контекст для агентов

Обновлено: 20.11.2026. Этот файл помогает войти в проект и продолжить работу. Перед изменениями сверяйте описание с текущими исходниками.

## Цель и границы проекта

Пользователь делает локальную вики и калькулятор по **BitCraft Online**. Интерфейс поддерживает русский и английский. Локальный каталог поддерживает все десять языков игры после импорта из Steam. Английские названия остаются в скобках и доступны для поиска.

**BitCraft Companion** — статический сайт. **«Рецепты»** соединяют игровой каталог с планировщиком производства. Доступны поиск, способы получения, цепочки ингредиентов и предыдущих тиров, запасы и базовое время. **«Справочник»** связывает профессии, знания и квесты с карточками предметов. Полнота игровых сведений и соответствие текущему серверу не заявляются.

Начните с этого файла, затем прочитайте [README.md](README.md), вычислительное ядро [web/domain.js](web/domain.js) и файлы, относящиеся к текущей задаче.

**Перед любой правкой интерфейса обязательно прочитайте [docs/UI_TARGET.md](docs/UI_TARGET.md).** Это таргет утверждённой «Лунной обсерватории»: палитра, композиция, компоненты, размеры, адаптация и правила проверки. Новые экраны и исправления должны сохранять эту систему. Эталонные PNG находятся в локальной папке `docs/design/lunar-observatory/`; снимки в `output/` являются результатами проверок и не заменяют эталоны. Обновляйте таргет при порученном пользователем изменении направления, не подгоняйте его под случайное отклонение кода.

## Игровые сведения из PDF

Все числа этого раздела относятся к указанному выше снимку. В коде дата хранится как `DATA_SNAPSHOT = '2026-11-13'`.

### Редкость и тир снаряжения

Редкость и тир - разные характеристики. Шанс в таблице относится к повышению **с предыдущей редкости на одну ступень** при повышении тира или подходящей перековке (PDF, стр. 1-2).

| Редкость | Английское название | Шанс перехода с предыдущей | Доступна с тира |
| --- | --- | --- | --- |
| Обычная | Common | Базовая | T1 |
| Необычная | Uncommon | 30% | T2 |
| Редкая | Rare | 15% | T3 |
| Эпическая | Epic | 7,5% | T4 |
| Легендарная | Legendary | 3,75% | T5 |
| Мифическая | Mythic | 1,875% | T6 |

- Неудача сохраняет редкость. Выше Mythic ступеней нет; на T7-T10 предел остаётся Mythic.
- Минимальные тиры относятся к стандартной цепочке крафта снаряжения. Не переносите их автоматически на материалы и особые предметы.
- Перековка (Recraft) использует сам предмет, лом подходящего типа и тира и Reforging Solvent; тир сохраняется. Количество лома зависит от конкретного рецепта, слота и редкости. Универсальной стоимости в PDF нет.
- По справочнику, в проверенном выборе исхода нет счётчика предыдущих неудач. Упомянутая на стр. 5 событийная защита от невезения через обмен Halloween-предметов - отдельная механика.

Модель распределения на стр. 3: старт с одного Common T1, по одному улучшению на каждый следующий тир, без дополнительных перековок. За один шаг редкость сохраняется или растёт на одну ступень. Контрольные значения: Mythic на T6 примерно `0,0002373%`, на T10 примерно `0,020109%`. Это вероятность результата **полной цепочки**, а не вероятность одной перековки Legendary.

### Конкретные шансы добычи

Редкость предмета сама по себе не определяет шанс его выпадения. Важны предмет, источник, тир исходного объекта и единица попытки (PDF, стр. 4).

| Результат | Редкость | Одна попытка | Шанс |
| --- | --- | --- | --- |
| Rangifer Antler / Рог рангифера | Rare | Убить одного Rangifer; выдача дропа с врага | 2% |
| Preserved Mushroom / Сохранившийся гриб | Legendary | Опознать один Unidentified Basic Mushroom, T1 | 0,2% |
| Berserker Mushroom / Гриб берсерка | Epic | Опознать один Unidentified Simple Mushroom, T2 | 2% |
| Enormous Trask Scale / Огромная чешуя | Legendary | Разделать одного Enormous Trask, T1, на Fishing Station | 3% |
| Hardened Lobster Chitin / Прочный хитин | Epic | Cut Up одного Fine Lobster, T4 | 0,5% |
| Hardened Lobster Chitin / Прочный хитин | Epic | Cut Up одного Peerless Lobster, T6 | 1% |
| Hexite Infused Lobster Chitin / Хитин с хекситом | Mythic | Cut Up одного Flawless Lobster, T10 | `1/251`, примерно 0,3984% |
| Coralith / Коралит | Legendary | Обработать одну Ornate Geode, T7, на Masonry Station | 0,5% |
| Damaged Ancient Connector / Древний соединитель | Mythic | Получить содержимое одного Ornate Desert Chest | 1,5% |

Важные ограничения:

- 3% для Trask относится к разделке **уже пойманной** рыбы. Вероятность её поимки здесь не учтена.
- Для хитина T10 сохраняйте точное `1 / 251`, а не округлённый процент. Для соединителя PDF приводит `30% × 5% = 1,5%`.
- Coralith указан именно для геоды T7; два источника Hardened Lobster Chitin имеют разные шансы.
- Один удар по ресурсному узлу не обязательно равен одной проверке дропа. Нельзя без проверки пересчитывать шанс на проверку в шанс на клик или целую жилу.
- Актуальный процент ракушек из песка в PDF отсутствует: отмечено снижение шанса без нового числа. Не подставляйте старое значение или догадку.

### Математика калькуляторов

В вычислительном ядре вероятность `p` - доля от 0 до 1; в интерфейсе - проценты. Количество попыток `n` и цель `k` - целые неотрицательные числа.

Для независимых попыток с постоянным шансом и одним успехом на успешную попытку:

- Хотя бы один успех за `n` попыток: `P = 1 - (1 - p)^n`.
- Среднее число попыток до первого успеха: `1 / p`; до `k` успехов: `k / p` при `p > 0`.
- Для одного успеха и заданной вероятности `q`: `n = ceil(ln(1 - q) / ln(1 - p))` при `0 < p < 1` и `0 < q < 1`.
- Для `k` успехов используется хвост биномиального распределения: `P(X >= k)`, где `X ~ Binomial(n, p)`. Формула для одного успеха не заменяет этот расчёт.
- Граничные случаи `p = 0`, `p = 1`, `k = 0`, `q = 0`, `q = 1` обрабатываются отдельно; существующие функции ядра это учитывают.

Среднее не является гарантией. При `0 < p < 1` конечное число попыток не обеспечивает строгие 100%. Округлённые до 100% результаты тоже не означают гарантии. Не добавляйте модель накопления удачи без отдельного подтверждения механики.

Проверочный пример из PDF, стр. 2: Legendary -> Mythic, `p = 0.01875`. Среднее - около 53,33 попытки; минимум для 50% - 37, для 95% - 159; за 100 попыток вероятность хотя бы одного успеха - около 84,94%.

## Что уже реализовано

Текущий визуальный стиль — **«Лунная обсерватория»**, выбранный пользователем: тёмно-синяя основа, бирюзовые показатели, янтарные акценты и тонкие мотивы созвездий. Добыча и перековка используют кольцевой показатель вероятности и компактную карточку предмета. Вкладки, таблицы и диалоговые окна поддерживают общую тёмную тему.

Редизайн меняет оформление и компоновку интерфейса. Архитектура, ключ localStorage `bitcraft-companion-v1` и схема экспорта `version: 1` сохранены; существующие планы и параметры расчётов читаются без миграции.

Начальные рецепты **учебные**: «Набор для похода», «Доски», «Верёвка». Они демонстрируют расчёт и не подтверждены как игровые рецепты. Не включайте их в вики как достоверные данные.

С 18.11.2026 в каталоге есть секция `guide` из того же локального снимка. В карточках предметов 218 обменов индексируются по тому, что путешественник отдаёт и принимает. Награды квестов привязаны к предметам и разделены по источнику выдачи. Характеристики экипировки относятся к конкретной редкости. Для действий «Рассчитать добычу» используются девять пресетов PDF и точные `methodKey` из `DROPS`. Прогрессия связывает уровень с требованиями рецепта, условиями ношения инструментов и таблицей знаний.

Учебные и пользовательские рецепты остаются в режиме **«Ресурсы → Мои рецепты»**, в `state.resources`. Игровой справочник по умолчанию использует `state.resourceCatalog`: выбор, фильтры, количество и режим; запасы общие с `state.recipeBook.inventory`. Индекс материалов выводится из входов рецептов и источников добычи; снаряжение, служебные списки и скрытые записи не включаются в обычный список. Категории — группировка интерфейса по исходным тегам, а не новая игровая механика. Игровая книга использует отдельное `state.recipeBook`. Для количества снаряжения без требования редкости есть семейства `family:item:<id>`: например, 10 Rathium Pickaxe T6 раскрываются через 10 кирок T5 и ниже. Семейства объединяют реальные варианты одного имени, тира и категории; допуск в расчёт требует одинаковых норм, базового времени и требований вариантов. Точная случайная редкость, Recraft, добыча и служебные `Resolve Item` не превращаются в гарантированное производство. Альтернативы и внешний источник выбираются отдельно для ветвей; цикл остаётся видимой внешней потребностью.

Карточка конкретной редкости сохраняет свой ключ и характеристики. Если для точной редкости нет гарантированного способа, а для семейства он есть, производственный план по умолчанию использует семейство. Явный выбор редкости хранится в `recipeBook.rarityPreference` и относится к ключу карточки. Ручные способы старых планов сохраняют область расчёта. Пункт «Автоматически» снимает ручное назначение способа для выбранной ветви.

`item_list` — выбор одной группы по относительным весам, а все предметы внутри выбранной группы выдаются совместно. Значения 95/5 или 299/1 валидны; это не проценты. Гарантированный выход — минимум количества по всем положительным исходам. Исходные веса сохраняются. Не переносите эту трактовку автоматически на поле `probability` в таблицах добычи.

Режим **«Ресурсы → Постройки»** добавлен 15.11.2026: 807 видимых зданий из того же локального снимка. В `resourceCatalog.mode` используется значение `buildings`, фильтр функции хранится отдельно в `buildingCategory`; формат экспорта остаётся `version: 1`. У зданий в источнике нет единого тира: фильтр уровня сопоставляет `functions[].tier` и функцию в одной записи. Имена и категории функций взяты из `building_type_desc`; отрицательный уровень показывается как неуказанный. Связь с рецептами станции выводится из `requirements.station.buildings`. Строительство и разборка остаются справкой с нормами на одну операцию, `seconds: null`; автоматический план производства их не раскрывает. Показываются также исходные требования технологий поселения, интерьера, покрытия и шардов; идентификаторы без расшифровки не подменяются придуманными названиями.

Режим **«Ресурсы → Существа»** использует записи `enemy_desc` из того же снимка. В список входят 59 животных и монстров. Добыча связана с существом по `origins`, а калькулятор открывается для совпавшего проверенного пресета. Состояние использует `resourceCatalog.mode = 'creatures'` и `creatureCategory`. Прямые ссылки `#/resources/creatures/enemy%3A9` открывают карточку существа.

Вкладка **«Мир»** использует `catalog.world` из того же снимка. В достижениях очки, коллекционные награды и предыдущие достижения берутся из полей `achievement_desc`. Число открытых участков хранится отдельно от текста описания. В биомах служебный Dev отсутствует в списке, ссылки на разведки индексируются по `biome_requirements`. Цели разведок используют ID ресурсов из `resource_clump_desc` или существ из `enemy_ai_params_desc` и `EnemyType`. Скрытый квестовый ресурс доступен по ссылке из разведки. Настройки `state.world` грузятся со значениями по умолчанию из старого экспорта v1. [Схема данных](docs/DATA_FOR_FRONTEND.md#мир) · [Веб-адреса](docs/WEB_PORT.md#адреса).

Биомы в карточках «Ресурсов» и «Рецептов» подтверждаются статическими настройками появления, помещениями с указанным биомом или разведкой. Прямая добыча получает биом своего источника. Условия посадки показаны отдельной строкой. Для обычных узлов без подтверждённой связи показано отсутствие данных. В профессиях уровни сгруппированы по T1–T10 с точным уровнем у каждой строки. Шрифтовые значки навыков представлены локальными иконками соответствующих предметов.

Вкладка **«Добыча»** использует `catalog.drops` из того же снимка. У записи есть источник и единица попытки. При гарантированном минимуме с переменной надбавкой считается шанс получить больше минимума. Для нескольких предметов за одну попытку модель считает удачные выдачи. Шансы девяти пресетов совпадают с каталогом. `state.dropBrowser` хранит подвкладку и фильтры, а план сохраняет выбранный источник, точный шанс и дату. [Схема и проверка правил](docs/DATA_FOR_FRONTEND.md#добыча).

Вкладка **«Данжи»** использует `catalog.dungeons` и ключ входа `building_id`. Точки врагов связываются с `enemy_ai_params_desc` через `traveler_ruin_entity_id`, а имена типов переводятся в числовые ID перечислением `EnemyType` из `region_schema.json`. У боссов пороги и исходные списки берутся из `contribution_loot_desc`, а для навигации раскрываются возможные предметы вложенных списков. Состояние `dungeons` хранит только выбор и поиск. Веб-маршрут содержит только ID карточки. [Схема данных](docs/DATA_FOR_FRONTEND.md#данжи).

Время игровой книги — базовая последовательная модель: активный крафт `time_requirement × actions_required` при скорости ×1, прогрессе 1 за действие и без критов; пассивный крафт при `is_passive` и требовании станции — `time_requirement` на операцию; преобразования — `time_cost`. Это не реальное время персонажа. Время неизвестной операции хранится `null`; сбор, бой, дорога, очереди, бонусы и параллельные станции не включены.

Расчёт ресурсов раскрывает ингредиенты по совпадению `id` с рецептом, учитывает общий пул запасов и остатков, выявляет циклы. Время - сумма последовательного крафта; сбор сырья, дорога и параллельные станции не включены. Время добычи задаёт пользователь. Запущенный таймер учитывает календарное время и после закрытия окна до паузы.

## Устройство проекта

`web/i18n.js` выбирает язык, форматирует даты и числа и подставляет сообщения из `web/messages-en.js`. Язык по умолчанию определяется настройками браузера. Ручной выбор хранится в `bitcraft-companion-language` в текущем профиле. `scripts/import-game-localizations.mjs` читает CSV из установленного клиента Steam и сохраняет проекцию в локальный пакет. `web/catalog-language.js` загружает выбранный официальный словарь и использует `catalog-ru.json` для прежних русских названий и поиска. Публичный выпуск берёт русские переводы из `data/public/`. [Схема и подготовка переводов](docs/DATA_FOR_FRONTEND.md#языки-интерфейса-и-каталога)

Сайт собирается из `web/`. В Windows `Start-Web.cmd` запускает готовый `dist-web/` на порту 4173 и открывает браузер. При отсутствии сборки скрипт подготавливает её. Используется системный Node.js либо Node из Codex. `npm run web:dev` предназначен для пересборки и запуска после правок. `web:build` собирает пакет, `web:preview` обслуживает готовую сборку. [Подробности и порядок размещения](docs/WEB_PORT.md).

Входные HTML и service worker указывают на согласованный неизменяемый выпуск в `dist-web/releases/<content-hash>/`. Пути каталога и изображений разрешаются через `runtime-config.js` относительно URL модуля. Сборка сокращает браузерный индекс до локальных `images` и включает проверенный HTTPS-индекс в публичный выпуск при наличии `data/public/remote-icons.json`. Источники и контрольные метаданные используются при подготовке и проверке набора.

Веб-навигация использует hash-адреса вкладок и карточек, без запасов и пользовательских планов в URL. Service worker кеширует базовый интерфейс, каталог и картинки пресетов; прочие картинки — по мере просмотра (до 200), полный пакет около 74 МБ загружается отдельным действием из справки. Обновление применяется пользователем после подготовки нового базового пакета; старые кеши сохраняются для открытых старых вкладок. Браузер может удалить кеш, поэтому его готовность проверяется; автономная работа требует первоначальной загрузки по HTTPS или loopback.

Сайт хранит состояние в браузере под ключом `bitcraft-companion-v1`. Перенос между браузерами использует JSON `version: 1`. `state-storage.js` проверяет актуальность копии и сохраняет её перед импортом. Web Locks сериализует записи, когда API доступен. Устаревшая вкладка приостанавливает запись и предлагает экспорт или открытие актуальных данных. Тесты работают в изолированных контекстах.

Сайт использует HTML, CSS и JavaScript ES modules. Расчёты выполняются на клиенте, игровые данные берутся из закреплённого снимка.

### Хранение пользовательских данных

Состояние хранится в localStorage текущего браузера под ключом `bitcraft-companion-v1`. JSON экспорта имеет `version: 1`. Импорт заменяет текущее состояние и предварительно сохраняет копию в `bitcraft-companion-v1-before-import`.

Текущие лимиты: 50 планов, 100 сессий, 100 пользовательских рецептов; импорт до 2 МБ. План ресурсов сохраняет снимок собственных рецептов и запасов. `recipeBook` хранит цель, фильтры, выбранные методы, запасы и commit каталога в `snapshot`. Количество в открытой форме начинается с 1 после смены цели и перезагрузки. Явно сохранённые планы содержат своё количество. Каталог хранится отдельно. При открытии плана с другой версией каталога показывается предупреждение. Старое состояние без `recipeBook` или `resourceCatalog` получает значения по умолчанию. Производственные планы открывают список работ, а действие «К расчёту» восстанавливает исходные параметры. `progress` хранит введённые количества отдельно от исходных запасов и входит в экспорт `version: 1`. Старые планы открываются с пустым прогрессом. При изменении структуры данных предусматривайте совместимость или явную миграцию; не очищайте пользовательский профиль ради проверки.

### Запуск и проверки

Для локальной работы используйте команды из корня проекта.

```powershell
# Запуск готового сайта в Windows
.\Start-Web.cmd

# Сборка и локальная раздача
node scripts/build-web.mjs
node scripts/serve-web.mjs

# Тесты, доступные из публичной копии
npm test
node scripts/test-web.mjs --public

# Полный набор при подготовленных локальных таблицах и игровых иконках
npm run test:full
node scripts/test-web.mjs

# Перегенерация каталога при наличии локальных таблиц
node scripts/build-recipe-catalog.mjs
node scripts/build-recipe-catalog.mjs --check
```

Для браузерной проверки скрипт запускает временный сервер в подпапке `/companion/`. Интерфейс, сохранения, навигация и автономный режим проверяются через Playwright в изолированных браузерных контекстах. [Требования и команды для отдельных сценариев](docs/WEB_PORT.md#проверки).

## Правила продолжения работы

- Сохраняйте локальную работу без обязательного интернета. Смену стека, облако и подключение аккаунтов не считайте уже согласованными требованиями.
- Разделяйте сведения из источников, математически вычисленные значения, пользовательский ввод и учебные примеры. Не выдавайте отсутствие данных за нулевой шанс.
- Для новых игровых чисел фиксируйте источник, версию/дату снимка, дату проверки и точную единицу попытки. Различайте тир исходного объекта и тир получаемого предмета.
- Английские названия сохраняйте рядом с русскими; русские переводы из PDF служат для удобства, их официальный статус не установлен.
- Формулы и пресеты меняйте в вычислительном ядре; сохраняйте отделение вычислений от интерфейса. Округляйте при показе, а не при хранении шансов.
- При изменении математики запускайте тесты ядра; при изменении интерфейса проверяйте затронутые сценарии. Для правок только документации проверяйте факты и ссылки на локальные файлы.
- Обновляйте этот файл при существенном изменении архитектуры, источников или статуса возможностей; пользовательские инструкции по запуску поддерживайте в README.

- Структура вики: какие разделы, сущности, поиск и связи нужны пользователю.

- Порядок обновления данных, выбор игровых версий и отображение расхождений между источниками.
- Дополнительные модели расчёта: параллельный крафт, сбор и дорога, стоимость рецептов - только при наличии входных данных и отдельной задачи.
